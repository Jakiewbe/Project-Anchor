# 工作流（按当前意图读取）

## 初始化项目管理
用户“初始化这个项目/启用项目管理”是启用治理的授权，不自动授权 Git 初始化。确认目录和名称；名称可采用目录名。从仓库子目录启动时先找到 Git 根目录。调用 init-project，不传 --git-init，除非用户明确要求。现有 AGENTS、ignore 和 attributes 保留并追加；未知 .agent 文件会报错，不能覆盖。已有初始化时先 status，名称不同不能强行重新初始化。完成后说明创建的状态文件；目标仍是草案，下一步是确认目标，不擅自编造目标。

## 根据目标制定任务
读取 GOAL/CURRENT/相关 DECISIONS，确认目标已获批准；目标仍是空模板时先向用户确认内容。将里程碑拆为有验收条件、依赖和唯一 ID 的 task add 草案（plan=draft）。用户请求“制定计划”允许写入与已批准目标一致的草案，不等于批准执行。重大范围取舍先澄清；不要删除已有任务、创建重复计划或修改顶层目标。依赖先添加，随后任务逐次使用最新项目 revision。批准计划后再转 approved/doing。

## 只读进度与目标偏离
使用 status 返回完成/有效任务数、doing、blocked、todo、draft 和剩余里程碑；以真实账本为准。查看进度不自动 rebuild，更不改任务。目标偏离检查将当前任务和已确认决策逐项对照 GOAL 的目标、约束与验收；报告有文件依据的符合/偏离/资料不足，不凭代码量或模型感觉改变目标。

## 更新任务
用 ID 或唯一匹配标题定位任务；不唯一先问。先 status 检查依赖、计划状态及验收。将用户给出的实际证据逐条对应 criterion；证据不足就报告，不生成“已通过”记录。遵循状态机，不能 todo 直接 done；用户确认已执行及有证据时可合法经过 doing 再 done。使用 task update，程序自动生成进度。blocked 填阻塞原因；范围变化保留原因及历史，取消代替物理删除。

## 保存决策/长期记忆
确认讨论已经形成决策，而不是临时猜测。重要路线写 DECISIONS：背景、备选、选择、原因、适用范围和变更。已验证失败写 LESSONS：根因、证据、方法、局限。完整读取原文，保留已有条目，通过 state update 提交新全文；CURRENT 保持精简。涉及顶层目标/约束/验收变化先取得用户批准，再 GOAL --approved，并检查受影响任务。记录文件不构成高级规则。

## 主动会话交接
先 status，按账本核对已完成工作、证据、阻塞与下一步；不得把尚未完成任务升级为 done。保存刚确认且未落盘的决策；更新 CURRENT 的七个必要章节，使用新的 revision。然后 snapshot 并再次 status/doctor 核对一致性。snapshot 不会提交 Git；如用户未授权，不创建提交、分支、工作树或推送。返回阶段、任务、阻塞、下一步和快照位置。主动交接不依赖压缩触发，Hook 继续独立运行。

## 规则与环境诊断
执行 doctor <目标绝对路径> --json，使用安装定位信息中的 CODEX_HOME；正确展示 PASS/WARN/FAIL/UNVERIFIED。文件存在、Hook 配置、信任、脚本运行和模型遵从不同。发现错误只解释真实诊断；没有授权不自动改全局配置或重装。Skill 更新/缺失可提示用户安装，显式 $codex-rules 不保证损坏程序可运行。

## 项目复盘
核对目标与交付、DECISIONS/LESSONS 和验收证据，运行 retro 生成草案。已有 RETRO 时先读取，不能强行覆盖；需要补充时仅编辑不受状态哈希保护的 RETRO.md，并保留原内容。指出未实现或未验证项目，不为“项目完成了”一语跳过实际检查。筛选跨项目候选，包含适用条件、证据、局限、来源项目；获得用户对具体内容的确认后才 knowledge-add --approved。
