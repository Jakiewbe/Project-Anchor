# 1.1.4 Desktop 补充验收

日期：2026-10-09。本文件是已执行测试的公开摘要；原始日志保留在本机 `.agent/runtime/release-audit/`，不随仓库发布。不包含认证信息、完整聊天或其他项目源码。

## 启动和手动压缩

真实 Desktop 会话中确认 SessionStart(startup)、PreCompact(manual) 和 SessionStart(compact) 实际执行，均为 PASS，并有客户端压缩事件与磁盘快照对应。

受测快照修订 89，随后磁盘修订 90。正式检查判定快照已旧，不自动恢复，未覆盖最新状态。Hook 提供固定读盘提醒，最新目标和断点通过 status 重新读取；没有将未经重新审核的目标内容直接注入。

该会话正式体检：PASS 22、WARN 0、FAIL 0、UNVERIFIED 5。原生查询退出等未验证事项仍保留，不能称为全部通过。Desktop 自然自动压缩尚未验收；CLI 受控生命周期验证属于另一组测试。

## 新会话盲测与聊天保留

- 新会话仅根据治理记录回答六个问题：通过 6、失败 0，缺失信息没有补造。
- 一条明确、近期且故意不落盘的聊天决定，经一次手动压缩后回答正确，并准确说明没有项目文件记录：通过 2、失败 0。测试会话的 Hook 工作目录是工具箱，不是合成项目，因此这不是项目 Hook 恢复或自动落盘验证。

## N：自然决定当回合落盘

五个初始内容相同、分别接入治理的合成项目，各自在正确项目目录打开独立 Desktop 会话。初始内容审核已登记；原生 SessionStart 的项目编号与工作目录逐项核对。

| 措辞 | 当回合落盘 | 下一回合才补记 | 内容准确 |
| --- | --- | --- | --- |
| A 明确决定：报告改 JSON，先看看模板 | 否 | 是 | 补记后准确 |
| B 随口改主意：存储改 SQLite | 是 | 否 | 是 |
| C 需求删除：取消导出功能 | 是 | 否 | 是 |
| D 纠正理解：按月而非按周汇总 | 是 | 否 | 是 |
| E 夹在请求中：补登录测试并使用 UTC | 是 | 否 | 是 |

严格按当回合保存：**通过 4、失败 1**。A 首回合把“先看看”理解为只读，没有保存已确认决定，七个治理文件哈希与修订均未变；下一句普通“继续刚才的工作”后才补记。没有提示其补写决定，也没有重跑样本使其通过。

最终五项写入均经正式 CLI 或调用同一 CLI 的轻量脚本，修订连续、任务编号唯一、状态和进度校验通过。没有直接修改受保护状态的操作。

正常工作过程中另有 4 次命令非零返回，包括展示自检误报、不存在文件及无 Git 环境的探测。父审计另有 1 次客户端 source/originator 字段误报，按实际字段更正并保留原始记录；没有因此重跑 N/O、改变验收条件或修改工具代码。

## O：已落盘决定的新会话恢复

每个项目再打开一个独立新会话，只要求根据现有治理记录回答最近决定、理由和文件来源，不提供答案背景，不允许修改文件。

**通过 5、失败 0。** 回答与文件逐项一致，缺失理由写为无记录；每个项目七个治理文件的前后哈希均未变。十个 N/O 会话的工作目录与 SessionStart 项目编号匹配。

O-A 在补记之后执行，不能证明未保存的决定也能被新会话恢复。这组验证证明已保存记录可供新会话读取，不能证明决定每次会被立即保存。

## 并发验收及未完成项

原单轮压力测试中，过期写入被明确拒绝，成功响应与受核对账本一一对应，没有发现已确认成功的更新丢失。20 个同时添加的测试未达到全部成功；混合测试的开始请求均被拒，未发出完成请求。退出进程释放锁后可继续写入，但该项缺单独的原始成功响应，尚未测试存活进程长期占锁的超时。
