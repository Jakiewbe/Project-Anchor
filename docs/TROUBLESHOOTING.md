# 故障排查

| 问题 | 已知含义 | 处理方式 |
| --- | --- | --- |
| Python 版本不足 | 默认 python 可能是旧版本 | 使用 py -3 --version 确认 3.11+，Windows 使用 py -3 kit.py |
| Hook 已配置但不执行 | 配置、启用和信任不同 | 重启本地 Codex，在 /hooks 审核当前定义，检查 features.hooks、管理策略及日志 |
| Hook 信任显示 UNVERIFIED | 工具不读取未公开的原生信任磁盘格式 | 在实际 Codex /hooks 查看；脚本日志不能替代该检查 |
| 项目文件内容未注入 | 未审核或 GOAL/CURRENT 哈希已变 | 先审核资料，再 trust-project --approved；不必为任务账本单独信任 |
| CURRENT 修订警告 | 任务已更新但断点未同步 | 更新 CURRENT，保留必要章节，用当前项目修订号写入 |
| 修订冲突 | 另一个进程已经写入 | 重新 status，阅读新状态后重新决定修改，不自动重试覆盖 |
| 状态哈希不一致 | 文档被外部修改或损坏 | 先查文件；已审阅单个 Markdown 用 state adopt，损坏则从可靠检查点恢复 |
| 事务未完成 | 进程终止或回滚失败 | 停止其他写入，检查事务内旧/新内容，recover 继续或 --rollback；冲突文件需人工判断 |
| 锁超时 | 另一个进程持有写锁 | 等其结束；崩溃后 OS 自动释放，锁文件存在本身不代表锁被占用，不要盲目删锁 |
| PROGRESS 过期 | 派生文件被改动或未重建 | status --rebuild；账本损坏时先处理账本，不能由展示反推状态 |
| 安装或卸载拒绝 | 管理块/Hook 组漂移、重复或缺清单 | 对照备份与当前内容；保留用户编辑，不拿旧备份整文件覆盖新配置 |
| 指令覆盖或大小警告 | 原生加载链与模板不同 | 检查全局/项目 AGENTS.override.md、fallback 和 project_doc_max_bytes；在客户端核对 |
| config.toml 无法解析 | 现有配置损坏或编码错误 | 修正真实 TOML 后再安装；工具不会猜测修复或重写无关配置 |
| 快照异常或数量偏多 | 损坏、不明或其他项目快照被保留 | 人工检查再处理；工具只清理校验通过的本项目快照 |
| Hook 非零但压缩继续 | 默认不阻断压缩 | 读取 systemMessage、stderr、运行日志，先修复状态，再手动 snapshot 验证 |
| 日志写入失败 | 沙箱/权限、容量或单条日志超过上限 | 日志失败本身会使 Hook 报错，不能用旧日志证明本次成功；检查写权限和保留配置 |
| Windows/WSL 路径失效 | 各环境的解释器和绝对路径不同 | 在各环境单独 clone/安装，不共享已生成 Hook 命令 |

日志：CODEX_HOME/codex-rules/runtime/hooks.jsonl 与 hooks.jsonl.1。快照：项目/.agent/runtime/snapshots。安装备份：CODEX_HOME/codex-rules/runtime/backups。运行数据不应提交到 Git。

工具只支持本地文件系统的常规协作写入。外部编辑器不遵守工具锁；并发人工编辑应暂停工具写入后再登记。网络盘、系统崩溃时的磁盘控制器持久性、自动多会话合并没有通过验收。

沙箱可能禁止写 CODEX_HOME 或 Hook 运行目录；在用户主动运行的终端安装，并给实际项目需要的最小写权限。不要通过关闭所有沙箱和审批来掩盖权限错误。
